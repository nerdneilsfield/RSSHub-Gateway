## 简介
RSSHub-Gateway 提供了全面的可观测性功能，包括 Prometheus 指标暴露、pprof 调试接口和结构化 JSON 日志输出。这些功能帮助用户监控系统健康状况、分析性能瓶颈并快速定位问题。本文档详细介绍了这些功能的配置和使用方法。

## Prometheus指标暴露机制

### 自定义指标列表
RSSHub-Gateway 暴露以下自定义 Prometheus 指标：

- **rsshub_gateway_requests_total**：网关请求总数，标签包括 `method`（HTTP 方法）、`group`（分组名）、`route_prefix`（路由前缀）、`status`（状态码）。
- **rsshub_gateway_request_duration_seconds**：网关请求持续时间（秒），标签包括 `group`（分组名）、`route_prefix`（路由前缀）。
- **rsshub_gateway_upstream_requests_total**：上游请求总数，标签包括 `group`（分组名）、`upstream`（上游主机）、`status`（状态码）。
- **rsshub_gateway_upstream_success_total**：上游成功响应总数，标签包括 `group`（分组名）、`upstream`（上游主机）。
- **rsshub_gateway_upstream_failure_total**：上游失败响应总数，标签包括 `group`（分组名）、`upstream`（上游主机）。
- **rsshub_gateway_route_success_total**：路由成功响应总数，标签包括 `group`（分组名）、`route_prefix`（路由前缀）。
- **rsshub_gateway_route_failure_total**：路由失败响应总数，标签包括 `group`（分组名）、`route_prefix`（路由前缀）。
- **rsshub_gateway_cache_hit_total**：缓存命中总数，标签包括 `provider`（缓存提供者）。
- **rsshub_gateway_cache_miss_total**：缓存未命中总数，标签包括 `provider`（缓存提供者）。
- **rsshub_gateway_upstream_health**：上游健康状态（1 表示健康，0 表示不健康），标签包括 `group`（分组名）、`upstream`（上游主机）。
- **rsshub_gateway_upstream_eject_total**：上游剔除总数，标签包括 `group`（分组名）、`upstream`（上游主机）。
- **rsshub_gateway_retry_total**：重试总数，标签包括 `group`（分组名）。
- **rsshub_gateway_fallback_total**：回退总数，标签包括 `from`（来源分组）、`to`（目标分组）。
- **rsshub_gateway_config_reload_total**：配置重载总数，标签包括 `result`（结果）。

### 监控价值
这些指标提供了对网关性能和健康状况的全面洞察。例如，`rsshub_gateway_requests_total` 和 `rsshub_gateway_request_duration_seconds` 可用于监控请求量和延迟，`rsshub_gateway_upstream_health` 可用于监控上游服务的健康状况。

### 配置Prometheus抓取任务
在 Prometheus 配置文件中添加以下 job 来抓取 RSSHub-Gateway 的指标：

```yaml
scrape_configs:
  - job_name: 'rsshub-gateway'
    static_configs:
      - targets: ['localhost:8080']
    metrics_path: /metrics
    params:
      accesskey: ['PROM_KEY_123']
```

确保 `accesskey` 与 `config.yaml` 中的 `metrics.accesskey` 配置一致。

## pprof调试接口使用方法

### 启用pprof
在 `config.yaml` 中启用 pprof 并配置访问密钥：

```yaml
pprof:
  enabled: true
  path: /debug/pprof
  accesskey: PPROF_KEY_123
```

### 使用pprof进行性能分析
通过以下命令获取性能分析数据：

- **CPU profile**：`go tool pprof http://localhost:8080/debug/pprof/profile?accesskey=PPROF_KEY_123`
- **Heap profile**：`go tool pprof http://localhost:8080/debug/pprof/heap?accesskey=PPROF_KEY_123`
- **Goroutine stack dump**：`curl http://localhost:8080/debug/pprof/goroutine?debug=2&accesskey=PPROF_KEY_123`

### 内存泄漏排查
使用 `go tool pprof` 分析 heap profile 可以帮助识别内存泄漏。例如：

```bash
go tool pprof http://localhost:8080/debug/pprof/heap?accesskey=PPROF_KEY_123
(pprof) top
(pprof) list <function_name>
```

## 结构化日志输出格式

### JSON日志字段解析
RSSHub-Gateway 使用 zap 库输出结构化 JSON 日志。日志字段包括：

- **ts**：日志时间戳。
- **method**：HTTP 方法。
- **path**：请求路径。
- **group**：匹配的分组名。
- **route_prefix**：匹配的路由前缀。
- **status**：响应状态码。
- **duration_ms**：请求处理时长（毫秒）。
- **retries**：重试次数。
- **fallback_chain**：回退链。
- **err_type**：错误类型。
- **error**：错误信息。

### 通过日志快速定位问题
通过分析日志中的 `err_type` 和 `error` 字段可以快速定位问题。例如，`err_type` 为 `timeout` 表示请求超时，`err_type` 为 `connect` 表示连接失败。

## 监控集成案例与最佳实践

### 监控面板构建
使用 Grafana 构建监控面板，展示关键指标如请求量、延迟、上游健康状况等。可以使用 Prometheus 作为数据源，并创建以下面板：

- **请求量和延迟**：使用 `rsshub_gateway_requests_total` 和 `rsshub_gateway_request_duration_seconds` 指标。
- **上游健康状况**：使用 `rsshub_gateway_upstream_health` 指标。
- **缓存命中率**：使用 `rsshub_gateway_cache_hit_total` 和 `rsshub_gateway_cache_miss_total` 指标。

### 最佳实践
- **定期检查指标**：定期检查关键指标，及时发现潜在问题。
- **设置告警**：为关键指标设置告警，如上游健康状况下降或请求延迟增加。
- **使用pprof进行性能调优**：在性能瓶颈时使用 pprof 进行深入分析。
- **分析日志**：定期分析日志，识别错误模式和异常行为。
